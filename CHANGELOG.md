# Changelog

## UNRELEASED

- **Fix: AskClaude no longer ships the volatile git-status block in read and none mode (issue #73)** — `includeGitInstructions` covers both Claude Code's git-workflow guidance and the `gitStatus:` snapshot it appends to the cached system prefix. The provider path already turns it off outright; AskClaude kept it because it runs Claude Code's native tools and the guidance is real there. But `read` and `none` mode disallow Bash, so nothing in those children can act on git guidance — all that remained was a block labelled "the git status at the start of the conversation" that the bridge recomputes on every call, inside the ephemeral-cached block that any working-tree transition then rewrites. Dropped for those two modes, kept for `full`.
- **Fix: a tool call Claude wrote as text no longer stalls the turn silently (issue #36)** — Claude occasionally serializes a tool call as literal `<invoke name="…">` text instead of a structured `tool_use` block, mostly on long 1M-context sessions. pi sees an ordinary finished answer and the work just stops, so the agent reads as having chosen to stop. The bridge now names the condition: a warning notify listing the tools that leaked, plus a debug line and a diag dump. It reports rather than recovers — synthesizing a real call from parsed text would execute a command that never arrived as a structured request, so any `<invoke>` block the model merely quoted becomes live.
- **Fix: Claude Code plugins no longer leak into pi sessions (thanks @Chaanks)** — the provider and AskClaude paths now disable every plugin the user's Claude Code settings enable, matching the existing `CLAUDE.md` and skill-listing suppression. A plugin's hooks, commands and agents are written for Claude Code, not for the harness actually running the session: superpowers' `SessionStart` hook injected a skill index stamped `EXTREMELY_IMPORTANT` ordering the model to call a `Skill` tool pi does not expose. On one account this also cut 79 slash commands to 19 and 66 skills to 7 — prefix the whole conversation re-sends every turn, from a hook whose output need not be byte-stable across the rebuilds this bridge performs. Disabled through the `--settings` flag tier, which outranks user/project/local settings, so the user's own Claude Code config is untouched and their plugins keep working under real Claude Code. The user tier is read from `CLAUDE_CONFIG_DIR` when set, since that is the profile the child actually loads.
- **Fix: a subagent's system prompt resolves instead of shipping pi's harness (thanks @schuettc)** — pi's system prompt widens after `before_agent_start`: an MCP server's tool descriptions merge in only once that server connects. So the prompt the provider is handed — the one pi-subagents embeds verbatim into a child via `ctx.getSystemPrompt()` at dispatch — is larger than what was captured (measured 23,479 chars against 10,988, diverging at the tool list). The child's turn then resolved against no capture, fell through to a verbatim side request, and shipped pi's harness to Claude Code, tripping the server's plan-eligibility check as a 400 "out of extra usage". The bridge now also records `ctx.getSystemPrompt()` at `agent_start`, so the widened prompt is an exact key and the main lane stops reaching for stable-anchor recovery.
- **Fix: an extension's own one-shot no longer fails the turn (thanks @schuettc)** — an extension can pull this provider's handle out of pi's model runtime (`ctx.modelRegistry.getRegisteredProviderConfig`) and drive it with a prompt of its own: a permission reviewer, a judge, a summarizer. Those landed on the conversation lane, where prompt-capture resolution rightly throws on a prompt pi never assembled. A single-user-message context whose system prompt neither resolves nor derives is now served as a side request instead. A resumed conversation whose prompt has drifted still derives and keeps its shared session.
- **Add: `edited_text_file` attachments survive a rebuild** — Claude Code attaches a file's fresh contents when something changes it underneath a turn, and those were dropped on every rebuild because they hang off a tool-result record, which had no position in the prompt-ordinal scheme. They are now anchored on the answered call's `tool_use_id`, which survives the round trip: Claude Code's `tool_use` id is the same id pi records as its `toolCallId`. Scanned over every Claude Code session on one machine, this takes the carried population from 12 to 303, all 303 placed at the message they really belong to (`diag/attachment-coverage.mjs`, which checks reconstruction against `parentUuid` ground truth, not just resolution). An attachment whose tool call pi never recorded — an AskClaude child running a tool of Claude Code's own — is still dropped, which is the right answer for context whose parent turn is not being rebuilt either.
- **Fix: a shifted prompt ordinal no longer silently drops a carried `@file`** — the two sides count prompts differently, so any session that at-mentions a file, steers mid-turn and then rebuilds lost every carry after the first steer; aborts alone are 46% of rebuilds and Claude Code's own `[Request interrupted by user]` record shifts the count the other way. Placement keeps the ordinal as its fast path and now falls back to the parent text the ordinal only ever existed to confirm, taking it when that text identifies exactly one prompt and still refusing when it is ambiguous.
- **Fix: provider registration is per session (thanks @KaviiSuri)** — a `ModelRegistry` belongs to a session, not a process, but the re-registration guard assumed every later module instance was a subagent sharing its parent's registry and skipped registering entirely. A host that runs several independent sessions in one process left every session after the first with no `claude-bridge` models at all — silently, and depending on which session bound first, so it looked intermittent. Registration is now unconditional and routed through one stable dispatcher shared by every registry, which keeps the property the guard existed for: a later registration installs the *same* function object, not a competing closure, so it cannot take tool routing away from an earlier session's in-flight state. The dispatcher also re-registers itself rather than throwing when it finds the live set empty, which a host that resumes a long-lived session without re-running `activate` can otherwise cause — that throw failed the turn and sent the host to a fallback provider that then rejected the same model.
- **Add: `toolChoice: "none"` is honoured (thanks @thurstonsand)** — a caller that asks for no tools, such as a summarizer or judge that throws when one comes back, was still handed pi's whole tool list. There is no `tool_choice` to forward through Claude Code, so the bridge now honours it the only way it can: `resolveMcpTools` advertises nothing. It is the single source of the MCP server and both name maps, so no call site can route around it.
- **Add: an oversized tool description is named instead of silently truncated** — Claude Code cuts every MCP tool description at 2048 characters when rendering it into the model prompt, so an oversized pi tool reaches the model amputated mid-sentence, reading as documentation that simply stops. pi permits any length, so the bridge cannot fix the truncation without moving per-tool prose into the cached prefix; it now warns once per tool instead, naming the tool and its length.
- **Fix: AskClaude honours a model's own `thinkingLevelMap` (thanks @underactive)** — the provider path already preferred pi-ai's per-model effort overrides over the bridge's generic table; AskClaude used the generic table unconditionally.
- **Add: `MUSTER_HOOK_DISABLE=1` in every Claude Code child (thanks @schuettc)** — the child inherits `$TMUX` and the pane's process ancestry, so a user's `muster hook` SessionStart/SessionEnd hooks reclaimed and then tombstoned the *hosting pi session's* bus row on every request, leaving the pane permanently "departed". Inert when muster is not installed.

- **BREAKING: requires pi 0.85** — the peer floor moves from `>=0.82.1` to `>=0.85.0`. The older floor was no longer tested against anything: dev peers now track 0.85.0, which is the only surface typecheck and the suite actually verify.
- **Bump: Claude Agent SDK 0.3.260 (Claude Code 2.1.260)** — the pinned 0.2.141 bundled Claude Code 2.1.141 from May, which predates the Fable models this bridge already advertises: `claude-fable-5-1` is rejected with an API 400 below CC 2.1.251, and the moving `fable` alias only points at Fable 5.1 from 2.1.258. `@anthropic-ai/sdk` (types only) moves to ^0.123.0 to satisfy the new peer floor, and `@modelcontextprotocol/sdk` to ^1.30.0. Typecheck and the unit suite pass; `tests/int-cc-contracts.mjs`, which pins the undocumented CC behavior the bridge depends on, has NOT been re-run against the new SDK and should be before release.
- **Bump: pi 0.85.0 and the dev toolchain** — dev peers to 0.85.0, TypeScript to 7, tsx to 4.23.13, `@types/node` to 24.13.3. Two version-tracking choices are deliberate rather than "newest wins": `@types/node` follows the Node 24 runtime rather than jumping to the Node 26 types, and `typebox` is pinned to the exact 1.3.7 pi bundles, since pi's loader aliases that import to its own copy and typechecking against a later minor would compile against API the runtime does not have. `@earendil-works/pi-server` is added as a devDependency because pi-coding-agent 0.85.0 reaches it through `experimental/server.js` without declaring it, so importing the package from the test harness fails without it.
- **Tests: the streamFn inventory probe follows npm's layout** — it hard-coded `pi-coding-agent/node_modules/@earendil-works/`, which only exists while our dev peer range disagrees with pi-coding-agent's own. On 0.85 the two dedupe and the pair hoists to the top level, so the probe now takes the first candidate tree that actually holds them and fails with a legible message if a future layout is neither. The inventory itself still passes against 0.85 — pi added no new streamFn consumers.
- **Fix: Claude Code ran in the host process's directory, not the session's (thanks @pfurini)** — pi's stream options carry no `cwd`, so `options?.cwd ?? process.cwd()` never took its first branch and every spawn — provider, compaction summary and AskClaude — was anchored on wherever the host process started. In the TUI those coincide, which is why it went unnoticed; for an SDK or harness caller that sets a session cwd they do not, and the spawned Claude Code then resolved project skills, settings and relative paths against a different project. `ExtensionContext.cwd` is cached on `session_start`, AskClaude takes its own from the invoking tool's context, and `process.cwd()` drops to a last resort.
- **Fix: a settled query's parked Claude Code child survived host shutdown (thanks @pfurini)** — `clearSession` nulls the shared session and the stream-function global but never touched `activeQueryContexts`, and the SDK spawns `claude` with no parent-death watchdog, so a child parked at a tool boundary under a query that *settled* (rather than aborted) reparented on host exit and kept billing the subscription. `session_shutdown` now drains and kills every live query first, owner-gated so a non-owner same-cwd session's shutdown cannot tear down the owner's queries. Draining is best-effort but the kill is not: a context whose drain throws is still interrupted, closed and removed.
- **Fix: a rebuilt system prompt is recovered by stable anchor, not by portable-part overlap (thanks @jabrown93)** — the previous tolerant match ran *before* the embedded-prompt route and accepted any capture whose custom/append/context files all appeared in the prompt, so a prompt that merely wrapped a capture resolved to the inner capture and silently dropped the wrapper's own instructions. Recovery now runs last, keys on a churn-invariant anchor that identifies one agent (its `<project_context>` block, its custom/replace prompt or a sub-agent's own slices of it, or a stable append), holds an identity floor so a coincidental short substring cannot resurrect a capture, ranks by most specific node so a sub-agent is recovered rather than its parent, and refuses outright when a sibling sharing the project block makes the anchor ambiguous. Each recovery is written to `claude-bridge-diag.log`, since the recovered skills can lag the rebuild by one `before_agent_start`.
- **Fix: `/model claude-fable-5` selected Fable 5.1 (thanks @jabrown93)** — `resolveModel` returned the first partial match, and `claude-fable-5-1` is both listed first and contains the older id. An exact id now wins over any partial match, which also disarms the same trap for future point releases.
- **Add: tool calls stream their arguments (thanks @thurstonsand)** — Claude Code does not request the `fine-grained-tool-streaming-2025-05-14` beta, so the API buffered and validated tool-input JSON before releasing it: a write or bash call showed its name, froze for seconds, then filled instantly, while text and thinking streamed normally. The bridge adds the beta to `ANTHROPIC_BETAS` in the child environment, merged with any value the user already set.
- **Fix: keep rebuilt Claude sessions aligned with Pi's current history and model (issues #30, #42, #55, #62)** — shrinking or compacting history now rebuilds instead of silently starting without context, completion preserves pending rebuilds, cursors track current history, and model changes invalidate the session.
- **Fix: classify and recover from Claude stream failures (issues #35, #43, #58)** — exhausted subscription limits reach Pi's model fallback, a transient overload before output retries once, and a tool-aware watchdog aborts half-open streams.
- **Add: `/usage` command and quota footer** — the bridge records the subscription rate-limit windows the Claude Agent SDK streams each turn and shows the 5-hour utilization in the footer. `/usage` prints a bar for each window that has streamed in, with reset times, plus an Extra Usage in-use flag. Only windows the SDK actually emits are shown; windows that do not apply to the account are not referenced. No credentials are read. Exact credit spend and per-model limits are not in the stream, so `/usage` points at Claude Code's own `/usage` for those.
- **Fix: another extension's own agent loop killed pi** — an extension that drives its own `agentLoop` is served by pi-ai's default stream function, which resolves the api id in pi-ai's registry rather than in pi's model runtime, where `pi.registerProvider` put the provider. On a bridge model that threw "No API provider registered for api: claude-bridge", and since `agentLoop` never catches its own rejection, the process exited. The bridge now registers there too and serves such a call as a self-contained Claude Code session: the caller's system prompt verbatim (no prompt-capture lookup, which cannot account for a prompt pi never assembled), the caller's tools over MCP, its own session deleted when the call ends, and no read or write of the shared session — including on failure, where the error path used to discard it. Setup failures are now reported on the stream instead of thrown, since the caller cannot handle a throw.
- **Fix: AskClaude reports its effective configured defaults (issue #65)** — its schema, description, and TUI now agree on mode and isolation, and disabling full mode removes it from the enum.
- **Add: Fable follows Claude Code's moving alias** — `claude-fable-5` and `claude-fable-5-1` now request `--model fable` (currently Fable 5.1, native 1M) instead of pinning `claude-fable-5[1m]`.
- **Fix: a re-assembled system prompt no longer fails the turn** — when another `before_agent_start` handler changes the active tool list (e.g. `rpiv-ask-user-question` strips its tool in non-UI runs), pi rebuilds the system prompt and the exact capture key no longer matches. `resolveOrDerive` now adopts the most recent capture whose portable parts still appear verbatim in the prompt, instead of throwing `prompt-capture: no capture`. Fixes every `pi -p` / subagent turn under such extensions.
- **Fix: isolated subagents can resolve their captured system prompt (issue #64)** — prompt captures now share one bounded process-wide registry across extension module instances.
- **Fix: git-status changes no longer bust the prompt cache (issue #73)** — the `claude_code` preset embeds a git-status snapshot in the cached system block, so any git transition (new file, staging, commit) rewrote the whole conversation prefix at cache-write rates. The provider path now sets `includeGitInstructions: false`, stripping the block with no other cost.
- **Fix: rate-limit warning showed 1% and repeated every request** — the SDK reports `utilization` as a fraction (0.98), but the notification rounded it directly, printing "1% used" at 98% of the window. It now shows true percentages and only re-notifies when usage rises past a new 5% step or the threshold changes, instead of once per request while over the threshold.
- **Fix: an exhausted Claude subscription never triggered fallback models (issue #58)** — Claude Code words a spent quota as "You're out of extra usage · resets 6:30pm", which names no recognizable symptom, so pi-subagents' `fallbackModels` and similar retry logic read it as a fatal error. A failure preceded by a rate-limit rejection is now labelled as one, with its limit type and reset time. Also fixes the rate-limit notification showing a 1970 reset time.
- **Fix: better isolate AskClaude tool (issue #59)** — AskClaude children no longer inherit the user's `~/.claude` `CLAUDE.md` files or skill listing, and now always get Claude Code's system prompt preset instead of only when pi-side skills exist. Thanks @JAtkinsonKO.
- **Fix: Bogus debug message about "record count mismatch" after switching providers** — the post-rebuild integrity check did not take `@file` expansion into account when switching providers.

## 0.7.0 — 2026-08-08

- **BREAKING: AskClaude tool now off by default** — If you want to continue using the AskClaude tool, set `askClaude.enabled` to `true` in your config (see README.md).
- **New: mid-turn steering actually works (issue #39)** — a steer sent while a tool was running used to be stashed and replayed as a follow-up after Claude's whole turn finished. The prompt is now a long-lived streaming generator and the steer is written to CC's stdin (`priority: "next"`) before the tool result is released, so CC drains it at that tool boundary and acts on it in the same turn.
- **Fix: system prompt loading** — Claude Code now receives the same global and hierarchical `AGENTS.md` / `CLAUDE.md` files that Pi loads. Config settings`provider.appendSystemPrompt` / `provider.settingSources` are no longer needed and have been removed gone). Improved compatibility with for children agent (i.e. subagents) and for other extensions that modify the system prompt. Unhandled system prompt configurations should fail loudly rather than silently discarding instructions.
- **Fix: branch summarization ran through the live provider** — rewinding or forking with "summarize" runs through the *agent's* stream function, so unlike `/compact` the request reached this provider and the live Claude Code session rather than an isolated subprocess. The bridge now takes over `session_before_tree` the way it already took over `session_before_compact`.
- **Fix: `@file` mentions were lost when a session was rebuilt** — Claude Code expands an at-mention itself (unlike pi) and stores the file's contents as an `attachment` record in its own session file; pi never sees it, so a rebuild kept the prompt text and silently dropped the file the model was reasoning about. Expansions are now carried across. Requires cc-session-io `^0.4.0`.
- **Fix: images dropped from prompts and rebuilt sessions (issue #34)** — an image followed by a trailing text preview lost the image, and tool results carrying images were flattened to text whenever the bridge rewrote pi's history into a Claude Code session. Images survive both paths now.
- **Fix: session rebuilds could corrupt turn structure** — pi records one message per tool result, and `repairToolPairing` (applied inside `Session.importMessages`, so unavoidable) only pairs results sharing the user message right after their assistant message, so tool results past the first can become `[no tool result recorded]`; a turn's results are now collected into one message placed directly after its assistant message. Minor: a turn aborted before anything streamed was rebuilt as `[incompatible content omitted]` potentially misleading the agent into thinking it is missing something. Empty turns are dropped now, while genuinely filtered content keeps its slot and label. Rebuilds also incorrectly wrote pi's bare model id instead of the resolved CLI id, dropping the `[1m]` suffix (issue #42; minor metadata fix only, since `--model` was already correct).
- **Fix: errored turns could report as a successful stop** — CC flags failures with `is_error` on a result whose subtype is still `"success"`, so the bridge duplicated the error text and finalized normally (issue #43); failed results now end the turn with `stopReason: "error"`, and the compact-summary path no longer accepts an errored result. Separately, a turn that ended on a tool call has its pi stream closed, and the guard suppressing content events for a closed stream also swallowed the `result` message, so a 429 or overload mid-tool set no `stopReason` and logged nothing (part of issue #35). The no-event stream watchdog idea in #35 has not been addressed.
- **Fix: a reentrant subagent could disturb the parent's session** — the shared session cursor was written from whichever context delivered tool results, so a background subagent dragged the parent's cursor backwards and cost its next turn a full rebuild and a flushed prompt cache. Removal from the active-context set is now guarded like the cleanups beside it, and an orphaned tool result no longer resets the live top-level context's turn state.
- **Fix: bridge could deadlock on a tool name Claude can't call** — Claude sometimes called `bash` instead of `mcp__custom-tools__bash`; CC rejected it with "No such tool available" and retried under a fresh tool_use id, but the bridge had already run the rejected call, so the retry's MCP handler waited on a result that never came. Calls for anything the bridge does not serve over MCP are now ignored. Rebuilt transcripts contributed to this by sometimes naming tools as `Bash`/`Read`/`Edit`/`Write` in past calls; those names now stay in the `mcp__custom-tools__` namespace.
- **Fix: nested tool schemas flattened (issue #44)** — converting pi schemas to Zod collapsed nested objects and dropped `anyOf`/`const`, so Claude saw only the top level of tools like `edit` and `subagent`. The MCP server now serves pi's JSON Schema verbatim.
- **Fix: tool results paired by call order** — MCP handlers took their `toolCallId` from a positional cursor, so a call arriving out of order silently paired its result with the wrong tool call. Now pairs by Claude's `_meta["claudecode/toolUseId"]` and fails loudly if it is absent.
- **Fix: Claude Code could write memory from bridge turns** — provider and AskClaude queries now disable auto-memory through the SDK; set `provider.autoMemoryEnabled` to `true` to opt in if you actually want it. Isolated compaction queries always disable it.
- **Tests: suites now drive the real code** — `tests/lib/record-sdk-streams.mjs` captures verbatim SDK streams (scrubbed, and refusing any fixture the username survived) for `tests/unit-stream-replay.mjs`, replacing hand-written messages that missed the `system/status` and `rate_limit_event` frames a real stream carries. `tests/int-shutdown-kills-cc.mjs` pins that a pi shutdown and a user abort each reap the Claude Code subprocess with a tool call in flight.
- **Tests: correctness audit tooling** — `diag/audit-{transcripts,cache,warnings}.mjs` scan session transcripts and the bridge log for silent data loss, prefix-cache breaks and stranded tool handlers, gated on `--since`; `diag/replay-write-path.mjs` replays any pi session through the rebuild. `tests/int-cc-contracts.mjs` pins the undocumented Claude Code behavior the bridge depends on against the installed SDK, and `tests/unit-convert-determinism.mjs` pins that a rebuild is deterministic and extends the previous transcript rather than rewriting it.
- **Internal: trim redundant dependencies** — pi bundles typebox and its extension loader always aliases the import to that copy, so shipping our own only made consumers install a redundant one that pi ignores. Now `peerDependencies: "*"` plus a devDependency for typechecking, as pi's packaging docs require; dev peers track pi 0.83.0. `@anthropic-ai/sdk` moves to devDependencies for the same reason — it is only ever imported for types.

## 0.4.0 — 2026-05-04

- **Fix: Opus 4.7 + xhigh sent wrong effort to SDK** — pi-ai 0.72 ships per-model `thinkingLevelMap` overrides (e.g. `claude-opus-4-7` declares `xhigh→xhigh`, not `xhigh→max`), but our hardcoded `REASONING_TO_EFFORT` table ignored them. Effort lookup now consults `model.thinkingLevelMap` first, falls back to the table for older pi-ai or unmapped levels. Forwarded `thinkingLevelMap` through `buildModels` projection.
- **Fix: zero out model cost in `buildModels`** — per-token pricing in the footer was wrong because models inherited pi-ai's non-zero cost fields, which pi then multiplied by the huge token counts from the SDK. Now explicitly zeroed so pi's footer shows no cost.
- **Use `tools: []` instead of `disallowedTools` blocklist** — switch from blocking specific tools to explicitly passing an empty tools list, preventing any new default tools from silently leaking into bridge sessions.
- **Disable CC-side autocompact (`DISABLE_AUTO_COMPACT=1`)** — pi already owns context management and propagates its own `/compact` to CC. Letting CC autocompact too double-flushed the prompt cache and raced pi's threshold; manual `/compact` in CC is unaffected.
- **Fix: pi `/compact` no longer triggers CC autocompact-thrashing (issue #8)** — pi's compaction shrinks its messages array, but `syncSharedSession`'s REUSE check (`slice(cursor)`) silently returned `[]`, so the bridge kept `--resume`ing the pre-compact CC session JSONL. Over long sessions CC's own autocompact then refilled within 3 turns and tripped its anti-thrashing guard. Now subscribes to pi's `session_compact` event and forces the next sync down the REBUILD path so CC sees the post-compact history. Also subscribes to `session_tree` (branch nav has the same shape).
- **Refactor: split `needsRebuild` into `needsRebuild` + `forceRotate`** — only the abort case needs UUID rotation (to dodge late writes from the dying CC subprocess). Compact/tree now rebuild in place, preserving the sessionId and not leaking orphan JSONL files into `~/.claude/projects/`.
- **Block user-installed MCP servers from leaking into bridge sessions** — pass `--strict-mcp-config` unconditionally and set `ENABLE_CLAUDEAI_MCP_SERVERS=0` in the spawned CC env, suppressing both filesystem (`~/.claude.json`, `.mcp.json`) and claude.ai cloud MCP servers. Override with `provider.strictMcpConfig: false`.
- **Consolidate config** — SDK plumbing (`appendSystemPrompt`, `settingSources`, `strictMcpConfig`) moved from `~/.pi/agent/settings.json` (`claudeAgentSdkProvider` block) to a `provider` block in `~/.pi/agent/claude-bridge.json`. Old location no longer read. Drop deprecated, unsafe `maxHistoryMessages`.
- **Bump deps** — `@anthropic-ai/claude-agent-sdk` → ^0.2.126; migrate to TypeBox 1.x (new import paths per pi-mono 0.69); pi devDeps → ^0.72.1. Extract `registerTool` schemas to const with explicit `<typeof params>` generic to avoid TS2589 deep-instantiation under TypeBox 1.x.
- **Internal: move sources into `src/`** — `index.ts` and the extracted modules now live under `src/`; screenshots under `assets/`. `pi.extensions` and published `files` updated accordingly.

## 0.3.1 — 2026-04-18

- **Fix: empty thinking blocks on Opus 4.7** — Opus 4.7 silently changed default `thinking.display` from `"summarized"` to `"omitted"`, so streams emitted `thinking_start` + `signature_delta` with zero `thinking_delta` events, leaving `ThinkingBlock.thinking == ""`.
